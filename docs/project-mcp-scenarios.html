Using the course server with your assistant

The course server is an MCP server (MCP: Model Context Protocol, the standard way an assistant calls outside tools). Your assistant (Claude Code, or another assistant that supports MCP, such as Kiro or Copilot) connects to it with your course token and reads the course’s pages, prices, milestones and checks from it. You do not need to name a tool or a file: ask in your own words. If the assistant cannot reach the server or does not find a fact, it should say so instead of guessing, and name the pages it used.

Words used below: a lease is your group’s AWS sandbox account for the term; the course LLM gateway is the course’s address for model calls, paid from your team’s keys; a git tag such as cp1 marks the commit you hand in.

This page lists questions teams ask, what the assistant should do, and what a good answer has. If an answer lacks what the third column lists, ask again, or ask the assistant where it took each fact from.

Course information you need now

You ask What the assistant should do What a good answer has
“What do we need to know from the course right now: what is due next, our budgets, and anything we must not get wrong in AWS?” read the course’s start page, the milestone list and the resources page the next milestone with its date and its git tag; the AWS budget per group lease and the model-call budget; the Region; how to name and tag resources; the account limits that catch teams out
“What is our AWS budget for the term, and how much can we spend on model calls now?” read the course pages that state the budgets AWS: 30 USD per group lease for the term. Model calls through the course LLM gateway: about 5 USD per team for tests and experiments for now; you ask for more when your team is ready for production use. Each with the page it comes from
“We’re writing the script that creates our first Lambda function. Which Region, names and account limits do we have to respect?” read the resources page the Region (ca-central-1), the name prefix and the tags the resources page requires, each quoted from that page; Lambda concurrency 10 in a lease (confirm in yours); Service Quotas is denied, so limits are read from each service’s own calls
“Our Spark job needs more memory. Can we use an m7g.2xlarge in our group lease?” read the resources page, then search no: the allowed m7g sizes are medium to xlarge, quoted from the resources page; how to confirm a size in your lease with a dry run of aws ec2 run-instances (the reply DryRunOperation means allowed); a larger size needs a request to the course staff
“Which models can our app call through the course LLM gateway, and what is the most output tokens one request may ask for?” search, then read the course values the model names to use in your code: qwen3.8-27b and qwen3.6-35b-a3b for chat, qwen3-embedding-0.6b for embeddings; at most 16,384 output tokens for one chat request; 120 requests a minute per key
“Our notes say we have 20 USD and the experiments are due Friday. Check them against the course.” read your notes, then the course pages the budget and the dates from the course server, not from your notes, and each place where your notes disagree with the course

Feedback on your proposal

You ask What the assistant should do What a good answer has
“Can you give us feedback on our proposal using the course’s checks?” find the proposal check, read it, and write docs/reviews/proposal-check.md a table of the checks, each marked stated, partial or absent, with the line of your files it rests on; for each gap: what your files say now, why it matters for your project, and one to three options; a first line recording which check and which server version it used; last, an empty “What we changed” section, for your team to describe and reflect on what you changed based on the review, with the GitHub issues you created; no grade
“We changed section 4 of our proposal. Recheck it against the course’s check.” read the previous review file and run the check again what improved since the last review, what is still open, and your “What we changed” section kept
“We’re about to tag cp1. What do we have to do before we tag it?” read the milestone list for Checkpoint 1 the date and what to hand in; an offer to re-run the proposal check if you changed the files it reads

What else is available

You ask What the assistant should do What a good answer has
“What can the course server do for us? List what’s available now and what comes later.” read the start page and the lists of milestones and checks the tools and what each is for; the checks open now and the ones that open later, with their milestone; the reading list, the course values and the prices
“Which course checks apply to our project right now, and which come later in the term?” read the lists of checks and milestones which checks are open now, which come later, and the milestone each belongs to
“Start of a new session: has anything changed on the course side since we last checked?” read the course server version recorded at the top of your newest review file, then ask the server what changed since that version each change since that version with what to do about it, or none
“We’re thinking of adding retrieval (RAG) to our app. What should we check or read before we decide?” read the start page, search, and read the reading list the course readings on retrieval and on cost, the code you can reuse, and the gateway limits; no check that the course does not have
