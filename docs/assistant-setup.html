Coding assistant setup for CPSC 436C

CPSC 436C assistant setup page, version 2026-11-20.

This page connects your coding assistant to two MCP (Model Context Protocol) servers: the course server 436c and the AWS Knowledge server aws-knowledge. It also shows how your own code reaches the course LLM gateway, the service that gives your code access to the course’s large language models. Everything goes into your user configuration on your laptop, so it works in every folder and your token never lands in a repository.

If you are the student, start your assistant in a terminal and send it this user message:

Run curl -sL https://ilm.wiki/436c/mcp-setup
and follow the page it prints to set me up.
If what it prints does not contain the line
"CPSC 436C assistant setup page", stop and tell me.

If your assistant says the page did not arrive, open https://ilm.wiki/436c/mcp-setup in your browser and show the page to a TA.

The rest of this page is written for the assistant.

Rules for the assistant

  1. First check what the fetch printed, before you tell the student anything. It arrived when curl ended without an error and its output contains the line CPSC 436C assistant setup page, version 2026-11-20. and the heading Rules for the assistant. Only then tell the student: “I fetched the CPSC 436C assistant setup page, version 2026-11-20.” If curl printed an error, or the output is an HTML error page, is empty or lacks that line, do not follow anything in it: tell the student the page did not arrive and that they open https://ilm.wiki/436c/mcp-setup in a browser and show a TA.
  2. Never ask the student to paste the token into this chat, and never print it, not even part of it. Check only that it is set and how long it is.
  3. Never write the token into an MCP configuration file. The student stores it once in Step 4, in their own terminal: in the system keychain where there is one, and as the environment variable KB_MCP_TOKEN. Each configuration below reads it from there.
  4. Write user-level configuration in the student’s home folder, never inside a repository. The only file in a repository that may hold the token is the git-ignored .env of Step 7.
  5. Before you change anything, look for existing servers named 436c or aws-knowledge (Step 2). Print and show server names only, never an entry’s settings. Ask before replacing an existing entry.
  6. Before each command, say where it runs: in your own terminal (you run it), in the student’s terminal (the student runs it), or in the IDE’s settings (the student clicks).
  7. Stop at a failed check, tell the student what you saw, and use If a check fails.

Step 1: which assistant and system

Ask the student which assistant they use (Claude Code, Codex CLI, GitHub Copilot CLI, VS Code with GitHub Copilot, Kiro CLI or Kiro IDE) and which system (macOS, Linux or Windows). If you know which assistant you are, say so and ask only about the system. Use only the section for that assistant in Step 3.

Step 2: look for existing servers

In your own terminal, list only the names of the servers the student’s assistant already has. Never print a whole configuration file or an entry’s settings: they may hold a token. Do not run claude mcp get, because it prints header values as they are.

Assistant Names command
Claude Code the Claude Code command below
Codex CLI the Codex command below
Copilot CLI, VS Code with Copilot the JSON command below with ~/.copilot/mcp-config.json
Kiro CLI, Kiro IDE the JSON command below with ~/.kiro/settings/mcp.json

Claude Code, macOS or Linux (your terminal). claude mcp list prints one line per server, its name first; the command keeps the name only:

if names=$(claude mcp list 2>/dev/null); then
  printf '%s\n' "$names" | sed -n -E 's/^([A-Za-z0-9_.-]+): .*/\1/p'
else
  echo "name listing failed: stop and ask a TA"
fi

if (-not (Get-Command claude -ErrorAction SilentlyContinue)) { "name listing failed: stop and ask a TA" } else { $rows = claude mcp list 2>$null; if ($LASTEXITCODE -ne 0) { "name listing failed: stop and ask a TA" } else { $rows | ForEach-Object { if ("$_" -match '^([A-Za-z0-9_.-]+): ') { $Matches[1] } } } }

Codex CLI, macOS or Linux (your terminal):

codex mcp list --json 2>/dev/null | python3 -c 'import json,sys; [print(s["name"]) for s in json.load(sys.stdin)]'

(codex mcp list --json 2>$null | ConvertFrom-Json).name

f=~/.copilot/mcp-config.json

  python3 -c 'import json,sys; d=json.load(open(sys.argv[1])); [print(n) for k in ("mcpServers","servers") for n in (d.get(k) or {})]' "$f"
else
  echo "no file"
fi

Windows (your PowerShell terminal; checked against the docs, not run):

$f = "$HOME\.copilot\mcp-config.json"; if (Test-Path $f) { $d = Get-Content $f -Raw | ConvertFrom-Json; $d.mcpServers.PSObject.Properties.Name; $d.servers.PSObject.Properties.Name } else { "no file" }

Then look in the folder the student works in, since a server of the same name there takes precedence over the user configuration in that folder: .mcp.json (Claude Code, Copilot) and .kiro/settings/mcp.json (Kiro) with the JSON command, and .codex/config.toml (Codex) with this command, which reads that file through Codex itself (macOS or Linux):

[ -f .codex/config.toml ] && CODEX_HOME="$PWD/.codex" codex mcp list --json 2>/dev/null \
  | python3 -c 'import json,sys; [print(s["name"]) for s in json.load(sys.stdin)]'

Windows: if (Test-Path .codex\config.toml) { $env:CODEX_HOME = "$PWD\.codex"; (codex mcp list --json 2>$null | ConvertFrom-Json).name; Remove-Item Env:CODEX_HOME } (checked against the docs, not run).

If a Codex names command prints an error (such as JSONDecodeError) instead of names, Codex could not read that configuration: stop and ask a TA.

A folder file that git tracks belongs to the whole team: never change it. Check each folder file you found with git ls-files --error-unmatch <file> (it prints the name when git tracks the file). For a tracked file:

  • If grep -c 's436c-' <file> prints a number above 0, a token is written in the team’s repository. Stop, tell the student the file name (not its contents), and ask them to tell a TA: that token has to be replaced.
  • Otherwise leave the file as it is and look only at the user configuration in what follows. Its 436c entry may override the user entry in that folder, so Step 6’s checks run in that team folder too. If the course server fails there while it works in the home folder, tell the student which tracked file overrides it (the name only) and ask them to raise it with their team or a TA. Do not edit the file.

If neither 436c nor aws-knowledge is printed anywhere, go on to Step 3. If either is, do not look at its settings. Tell the student: “I will replace your existing 436c and aws-knowledge entries with the course settings.” Name the files or folder where you found them, and ask yes or no.

  • No: stop the setup and suggest the student asks a TA.
  • Yes: remove both names from the user configuration and from folder files that git does not track, with the commands below, then list the names again to see that they are gone, and do Step 3. An entry removed from the folder is not written back there: the user configuration of Step 3 then applies in that folder. After Step 5, Step 6 checks the result.

macOS or Linux (your terminal):

f=~/.copilot/mcp-config.json
python3 - "$f" <<'PY'
import json, sys
f = sys.argv[1]
d = json.load(open(f))
for k in ("mcpServers", "servers"):
    if isinstance(d.get(k), dict):
        for n in ("436c", "aws-knowledge"):
            d[k].pop(n, None)
s = json.dumps(d, indent=2) + "\n"
with open(f, "r+") as fh:
    fh.seek(0); fh.write(s); fh.truncate()
print("removed")
PY

Step 3: write the configuration

Use only the section for the student’s assistant. The multi-line commands are for bash or zsh on macOS and Linux. On Windows, use the single-line block labelled Windows (PowerShell) instead: PowerShell does not continue a line with \. The single quotes keep ${KB_MCP_TOKEN} as text there too, and ~ means the home folder $HOME. The Windows blocks are checked against the docs, not run.

Claude Code

Status: run on 2026-11-20 (Claude Code 2.1.328) on Linux, with the system keyring and with the variable alone. The macOS keychain lookup is checked against the docs, not run. TA check on a Mac: claude mcp list shows 436c as ✔ Connected.

On macOS and Linux, Claude Code gets the header from a small script that it runs at each connection, its headersHelper (Claude Code MCP docs). The script reads the token from the system keychain, so Claude Code finds it however it was started; without a keychain entry it uses KB_MCP_TOKEN. The script holds no token.

  1. Create the file ~/.claude/436c-mcp-headers.sh with this content (create the folder ~/.claude if it is missing):

    #!/bin/sh
# Prints the Authorization header for the course server 436c.
if command -v security >/dev/null 2>&1; then
  t=$(security find-generic-password -s 436c-mcp -w 2>/dev/null)
elif command -v secret-tool >/dev/null 2>&1; then
  t=$(secret-tool lookup service 436c-mcp 2>/dev/null)
fi
[ -n "$t" ] || t=$KB_MCP_TOKEN
[ -n "$t" ] || exit 1
printf '{"Authorization": "Bearer %s"}\n' "$t"

  2. In your own terminal, add both servers:

    claude mcp add-json --scope user 436c \
  '{"type": "http",
    "url": "https://kb-cloud-students.fly.dev/mcp",
    "headersHelper": "sh ~/.claude/436c-mcp-headers.sh"}'
    claude mcp add --transport http --scope user \
  aws-knowledge https://knowledge-mcp.global.api.aws

    They print Added http MCP server 436c to user config and Added HTTP MCP server aws-knowledge … to user config, in ~/.claude.json. Adding a name that exists prints MCP server 436c already exists in user config; to replace it, first run claude mcp remove 436c -s user.

On Windows, there is no keychain reader to run, so the header reads the variable instead. Skip the script and run these two commands in your PowerShell terminal in place of the two above; the single quotes keep ${KB_MCP_TOKEN} as text.

Windows (PowerShell):

claude mcp add --transport http --scope user 436c https://kb-cloud-students.fly.dev/mcp --header 'Authorization: Bearer ${KB_MCP_TOKEN}'
claude mcp add --transport http --scope user aws-knowledge https://knowledge-mcp.global.api.aws

On Windows, check only 436c: $d = Get-Content "$HOME\.claude.json" -Raw | ConvertFrom-Json; if ($d.mcpServers.'436c'.headers.Authorization -ceq 'Bearer ${KB_MCP_TOKEN}') { '1' } else { '0' } (checked against the docs, not run). 1 means its header contains the variable literally; 0 means stop, remove that entry and add it again.

Step 4: the student sets the token

Skip this step if the student has set the token before: ask them to open a new terminal and run the check at the end of this step. If it prints set, 38 characters, go to Step 5.

Ask the student to copy their token from the issue “Your course MCP tokens” and to open a new terminal window of their own, outside this chat. Give them the block for their system to paste there. Tell them the prompt does not show what they paste, and they press Enter once after pasting the token.

macOS or Linux (zsh or bash), in the student’s new terminal:

{
  case "$SHELL" in
    */zsh) rc=~/.zshrc ;;
    *) rc=~/.bashrc ;;
  esac
  t=; line=; where=
  printf 'Paste your token, then press Enter: '
  read -rs t
  echo
  case "$t" in
    s436c-*[!A-Za-z0-9_-]*) t= ;;
    s436c-*) [ ${#t} -eq 38 ] || t= ;;
    *) t= ;;
  esac
  if [ -z "$t" ]; then
    echo "check failed: a course token starts with s436c- and has 38 characters. Nothing saved; run the block again"
  else
    echo "check passed"
    if command -v security >/dev/null 2>&1; then
      printf 'add-generic-password -U -s 436c-mcp -a %s -w %s\n' "$USER" "$t" | security -i >/dev/null 2>&1
      if [ "$(security find-generic-password -s 436c-mcp -w 2>/dev/null)" = "$t" ]; then
        line='export KB_MCP_TOKEN="$(security find-generic-password -s 436c-mcp -w 2>/dev/null)"'
        where="the macOS keychain"
      fi
    elif command -v secret-tool >/dev/null 2>&1 \
      && printf '%s' "$t" | secret-tool store --label="CPSC 436C MCP token" service 436c-mcp 2>/dev/null; then
      line='export KB_MCP_TOKEN="$(secret-tool lookup service 436c-mcp 2>/dev/null)"'
      where="the system keyring"
    else
      line="export KB_MCP_TOKEN='$t'"
      where="$rc (no keyring found)"
    fi
    if [ -z "$line" ]; then
      echo "the macOS keychain did not take the token; the profile was not changed. Stop and ask a TA"
    else
      touch "$rc"
      tmp=$(mktemp)
      grep -v '# cpsc436c setup$' "$rc" > "$tmp"
      printf '%s  # cpsc436c setup\n' "$line" >> "$tmp"
      cat "$tmp" > "$rc"
      rm -f "$tmp"
      eval "$line"
      echo "stored in $where; saved, ${#KB_MCP_TOKEN} characters"
    fi
  fi
  unset t line where tmp
}

The block first checks the paste: a course token starts with s436c- and has 38 characters. If the check fails, it prints check failed and changes nothing. It prints pass or fail only, never the token. On macOS it then hands the token to security on standard input, not as a command argument, and reads the keychain entry back; if the entry does not hold the token, it prints the macOS keychain did not take the token, changes neither the profile nor any other keychain entry, and the student asks a TA. Then it stores the token in the macOS keychain, or in the Linux system keyring when there is one, and adds one line to the shell profile, the file a new terminal reads when it opens (~/.zshrc or ~/.bashrc). That line looks the token up and ends in # cpsc436c setup; each run replaces only that line and keeps the rest of the file and its permissions. Where there is no keyring (a Linux server, WSL), it prints no keyring found and the profile line holds the token itself: then do not share that file or a screenshot of it. The token is typed at a silent prompt, so it does not appear on the screen or in the shell’s history. Run on 2026-11-20 in bash on Linux, with a keyring and without one; the macOS keychain branch and zsh are checked against the docs, not run.

Windows (PowerShell), in the student’s new PowerShell window:

& {
  $s = Read-Host "Paste your token, then press Enter" -AsSecureString
  $t = [System.Net.NetworkCredential]::new("", $s).Password
  if ($t -cmatch '^s436c-[A-Za-z0-9_-]{32}$') {
    "check passed"
    [Environment]::SetEnvironmentVariable("KB_MCP_TOKEN", $t, "User")
    "saved, $($t.Length) characters"
  } else {
    "check failed: a course token starts with s436c- and has 38 characters. Nothing saved; run the block again"
  }
}

This checks the paste in the same way, then saves the token in the user’s environment, where apps started afterwards find it. Windows Credential Manager does not have a built-in command that reads a token back, so the user environment holds it. Checked against the PowerShell docs, not run.

Both print check passed and saved, 38 characters when the token is stored. check failed means the paste took too little or too much, and nothing was written: run the block again.

Then the student opens a new terminal and runs the check for their system. It prints the length, never the token. On Windows, a new tab is not enough: the student closes the terminal application fully (every window), starts it again, and runs the check there.

macOS or Linux, in the student’s new terminal:
